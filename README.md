# คะนึงถึงโฮมสเตย์ — ระบบจัดการการจอง

ระบบจัดการโฮมสเตย์สร้างจากดีไซน์ Kanuengthueng Homestay v2 ใช้ React + Vite ฝั่งหน้าเว็บ และมีเซิร์ฟเวอร์ Node.js ขนาดเล็กเก็บข้อมูลกลางไว้ให้ทุกเครื่องใช้ร่วมกัน

- **ใช้บนเครื่องตัวเอง:** เก็บข้อมูลในโฟลเดอร์ `data/`
- **ใช้บนอินเทอร์เน็ต:** เก็บข้อมูลใน PostgreSQL ผ่านตัวแปร `DATABASE_URL`

## รันบนเครื่องตัวเอง

```bash
npm install
npm run dev
```

เปิด http://localhost:5173 ถ้าจะใช้งานจริงบนเครื่องนี้ ให้รัน `npm run build` แล้วตามด้วย `npm start` จากนั้นเปิด http://localhost:8787

## ใช้งานจริงแบบฟรี: Supabase + Render + LINE OA

| ส่วน | บริการ | ข้อจำกัดของแพ็กเกจฟรีที่ต้องรู้ |
| --- | --- | --- |
| ฐานข้อมูล | [Supabase](https://supabase.com) (PostgreSQL) | 500 MB · โปรเจกต์หยุดชั่วคราวถ้าไม่มีการใช้งานเกิน 7 วัน แต่ระบบนี้ใช้ฐานข้อมูลทุกวันอยู่แล้ว |
| เว็บ | [Render](https://render.com) (Web Service) | หลับเมื่อไม่มีคนเข้าเกิน 15 นาที เปิดครั้งแรกหลังหลับรอประมาณ 1 นาที · ใช้ได้ 750 ชั่วโมงต่อเดือน (พอสำหรับเปิดตลอด 1 เว็บ) |
| ปลุกเว็บไม่ให้หลับ | [UptimeRobot](https://uptimerobot.com) หรือ [cron-job.org](https://cron-job.org) | ตั้งให้เรียก `/api/health` ทุก 5–10 นาที เพื่อให้สำรองข้อมูล 03:00 และสรุป LINE ทำงานตรงเวลา |
| แจ้งเตือน | LINE Official Account (Messaging API) | แพ็กเกจฟรีในไทยส่งได้ 300 ข้อความต่อเดือน นับตามจำนวนผู้รับ |

### 1. สร้างฐานข้อมูล Supabase
1. สมัครที่ https://supabase.com แล้วกด **New project**
2. เลือก Region เป็น **Southeast Asia (Singapore)** แล้วตั้ง Database password (จดไว้)
3. เมื่อสร้างเสร็จ กด **Connect** แล้วเลือก **Session pooler** และคัดลอก URI
4. แทน `[YOUR-PASSWORD]` ด้วยรหัสผ่านจากข้อ 2 ค่าที่ได้คือ `DATABASE_URL`
5. ไม่ต้องสร้างตารางเอง เซิร์ฟเวอร์จะสร้างให้ตอนเริ่มทำงาน (`kt_state`, `kt_files`, `kt_backups`)

ต้องใช้ **Session pooler** เพราะ Render เชื่อมต่อแบบ Direct connection (IPv6) ของ Supabase ไม่ได้

### 2. อัปโค้ดขึ้น GitHub
สร้าง repository แบบ **Private** ที่ GitHub แล้ว push โปรเจกต์นี้ขึ้นไป ไฟล์ `.gitignore` กันไม่ให้ `.env`, `data/` และ `node_modules/` ถูกอัปขึ้นไปแล้ว

### 3. Deploy บน Render
1. สมัครที่ https://render.com (เข้าด้วยบัญชี GitHub ได้)
2. ไปที่ **New › Blueprint** แล้วเลือก repository นี้ Render จะอ่านค่าจาก `render.yaml` (Singapore, แพ็กเกจฟรี, Node 22, เวลาไทย)
3. กรอกค่า:
   - `DATABASE_URL` จากขั้นตอนที่ 1
   - `ADMIN_PIN` เป็นตัวเลขที่เดายาก อย่างน้อย 6 หลัก
   - LINE สองค่าเว้นว่างไว้ก่อน (ใส่ทีหลังได้)
4. กด Apply แล้วรอ build ประมาณ 3–5 นาที จะได้ที่อยู่แบบ `https://kanuengthueng.onrender.com`
5. เปิดที่อยู่นั้นแล้วใส่ PIN จากนั้นไปที่ **ตั้งค่า** แล้วกด **เริ่มใช้งานจริง (ล้างข้อมูล)** และใส่เลขพร้อมเพย์ของร้าน

### 4. ปลุกเว็บไม่ให้หลับ
1. สมัคร UptimeRobot แล้วกด **New monitor**
2. เลือกประเภท HTTP(s) ใส่ URL `https://<ที่อยู่ของคุณ>.onrender.com/api/health` และตั้ง Interval เป็น 5 นาที

### 5. ตั้งค่า LINE Official Account
1. สร้างบัญชีที่ https://manager.line.biz (แพ็กเกจฟรี)
2. ไปที่ **ตั้งค่า › Messaging API** แล้วกด **เปิดใช้ Messaging API** ระบบจะให้สร้าง Provider ใหม่
3. เข้า https://developers.line.biz/console แล้วเลือก channel ของบัญชีนั้น
   - แท็บ **Basic settings**: คัดลอก **Channel secret**
   - แท็บ **Messaging API**: ที่ **Channel access token (long-lived)** กด Issue แล้วคัดลอก
4. ใส่สองค่าใน Render (ที่ Environment ของ service):
   - `LINE_CHANNEL_SECRET`
   - `LINE_CHANNEL_ACCESS_TOKEN`

   กด Save แล้ว Render จะรีสตาร์ตให้เอง
5. กลับไปแท็บ **Messaging API**:
   - **Webhook URL** ใส่ `https://<ที่อยู่ของคุณ>.onrender.com/api/line/webhook` แล้วกด **Verify**
   - เปิด **Use webhook**
6. ใน LINE Official Account Manager ไปที่ **ตั้งค่าการตอบกลับ** แล้ว:
   - เปิด **Webhook**
   - ปิด **ข้อความตอบกลับอัตโนมัติ** ถ้าไม่ต้องการ
7. ใช้มือถือของเจ้าของเพิ่มเพื่อน LINE OA ของร้าน (สแกน QR ใน Manager) แล้วพิมพ์ `ลงทะเบียน <PIN>` ในแชท
   - ถ้าจะให้แจ้งเตือนเข้ากลุ่ม ให้เชิญ OA เข้ากลุ่มแล้วพิมพ์ในกลุ่มแทน
   - ข้อความทุกข้อความที่ส่งเข้ากลุ่มนับโควตาตามจำนวนสมาชิกในกลุ่ม
8. ในแอป ไปที่ **ตั้งค่า › ส่งข้อความทดสอบ**

คำสั่งที่พิมพ์ในแชท LINE OA ได้:
- `ลงทะเบียน <PIN>`: เริ่มรับแจ้งเตือน
- `ยกเลิกแจ้งเตือน`: หยุดรับ
- `id`: ดู ID ของแชท

ข้อความอื่นของลูกค้าระบบจะไม่ตอบ ใช้แชทกับลูกค้าตามปกติได้

### 6. ติดตั้งบนมือถือ (Android / iPhone)
ระบบเป็นเว็บแอป ไม่ต้องผ่าน Play Store หรือ App Store เปิดเว็บแล้วเพิ่มลงหน้าจอหลักได้เลย จะได้ไอคอนบ้านและเปิดเต็มจอเหมือนแอป

**Android (Chrome)**
1. เปิด `https://<ที่อยู่เว็บของคุณ>.onrender.com` แล้วใส่ PIN
2. กดเมนู ⋮ มุมขวาบน แล้วเลือก **ติดตั้งแอป** (Install app) หรือ **เพิ่มลงในหน้าจอหลัก**
3. กด **ติดตั้ง** ไอคอน "คะนึงถึง" จะขึ้นที่หน้าจอหลัก

**iPhone / iPad (ต้องใช้ Safari เท่านั้น)**
1. เปิดเว็บใน **Safari** แล้วใส่ PIN
2. กดปุ่มแชร์ (สี่เหลี่ยมมีลูกศรชี้ขึ้น) ที่แถบล่าง
3. เลื่อนหา **เพิ่มไปยังหน้าจอโฮม** (Add to Home Screen) แล้วกด **เพิ่ม**

หมายเหตุ: PIN จะถูกจำไว้ในเครื่อง การเปิดผ่านไอคอนบน iPhone จะแยกที่เก็บจาก Safari จึงอาจต้องใส่ PIN อีกครั้ง

### ข้อควรรู้เมื่อใช้แพ็กเกจฟรี
- **สำรองข้อมูลเอง:** สำรองอัตโนมัติทุกวันเก็บอยู่ในฐานข้อมูลเดียวกัน แต่ควรกด **ตั้งค่า › ดาวน์โหลดไฟล์สำรอง** เก็บไว้ในเครื่องสัปดาห์ละครั้งด้วย
- **รูปสลิป:** รูปถูกย่อเหลือประมาณ 150–300 KB ก่อนอัปโหลด ฐานข้อมูล 500 MB เก็บได้ประมาณ 2,000 รูป ดูพื้นที่ที่ใช้ได้ใน Supabase ที่ Reports › Database
- **เว็บหลับ:** ถ้าไม่ได้ตั้งตัวปลุกในขั้นตอนที่ 4 คนแรกที่เปิดเว็บหลังเว็บหลับจะรอประมาณ 1 นาที
- **ใช้งานเพิ่มขึ้น:** ถ้าใช้งานมากขึ้น อัปเกรดทีละส่วนได้ เช่น Render Starter หรือ Supabase Pro โดยไม่ต้องแก้โค้ด

## สำหรับนักพัฒนา

```bash
npm test
```

- `server/`: เซิร์ฟเวอร์
  - `index.js`: route, งานรายวัน, webhook LINE
  - `store.js`: เก็บข้อมูลในหน่วยความจำและกระจายการเปลี่ยนแปลง
  - `persist.js`: บันทึกลงไฟล์หรือ PostgreSQL
  - `line.js`: เรียก LINE Messaging API
- `src/App.jsx`: สถานะและตรรกะของแอปพนักงาน
- `src/lib/`:
  - `core.js`: วันที่ ราคา ห้องว่าง
  - `ops.js`: การซิงก์แบบส่งเฉพาะรายการที่เปลี่ยน
  - `sync.js`, `api.js`, `promptpay.js`
  - `seed.js`: ข้อมูลตัวอย่าง
- `src/views/`, `src/modals/`: หน้าจอของพนักงาน
- `src/public/`: หน้าของลูกค้า (`/book`, `/review`, `/pay`)

หมายเหตุ:
- ถ้าสองเครื่องแก้รายการเดียวกันพร้อมกัน ระบบจะเก็บค่าที่บันทึกทีหลังสุด
- ไฟล์ `.npmrc` เป็นการแก้เฉพาะเครื่อง Windows เครื่องนี้ ซึ่งตั้งตัวแปร `ComSpec` เป็น `C:\TEMP` ไฟล์นี้ไม่ถูกอัปขึ้น GitHub

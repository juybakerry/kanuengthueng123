### 5.2 สูตรคำนวณ
คืน (nights)        = check_out_date − check_in_date            // check_out ไม่นับเป็นคืน
จำนวนแขก (guests)    = adults + children
รายรับการจอง         = Σ ทุกคืน (ราคาต่อคนของคืนนั้น × guests) − ส่วนลด + รายการเพิ่ม
ต้นทุนอาหาร          = 60 × guests × nights
ต้นทุนรถรับส่ง        = 200 × guests        (เฉพาะการจองที่เลือกใช้รถ)
ค่าแม่บ้านของช่วงเวลา = 300 × จำนวน “วันที่มีแขกพักอย่างน้อย 1 คน” ในช่วงนั้น
                      // คิดรวมระดับวัน ไม่ใช่ต่อการจอง: 2 การจองในคืนเดียวกัน = 300 บาท
กำไรสุทธิของช่วงเวลา  = รายรับ(ตามคืนที่พัก) − อาหาร − แม่บ้าน − รถ
                      − ค่าใช้จ่ายจากปัญหา(ตามวันจ่าย) − ต้นทุนคงที่ + เงินเรียกคืนจากลูกค้า
Occupancy (คน)       = คืน-คนที่ขายได้ ÷ (24 × จำนวนคืนในช่วง) × 100
Occupancy (ห้อง)     = คืน-ห้องที่มีการใช้ ÷ (5 × จำนวนคืนในช่วง) × 100
ยอดมัดจำ             = ปัดขึ้นเป็นจำนวนเต็มบาท(รายรับการจอง × 50%)
สถานะชำระ            = ยอดรับ = 0 → ยังไม่ชำระ · 0 < ยอดรับ < ยอดรวม → มัดจำ · ยอดรับ ≥ ยอดรวม → ชำระครบ
เงินเก็บเป็นจำนวนเต็มหน่วย “สตางค์” (integer) ทั้งในฐานข้อมูลและโค้ด ห้ามใช้ float · วันที่เข้าพักเก็บเป็นชนิด date ตามเวลาไทย (Asia/Bangkok)

ฐานข้อมูล: GitHub Actions รัน pg_dump ทุกวัน 03:00 (เวลาไทย) เก็บไฟล์ลง repo ส่วนตัว แยกจากโค้ด เก็บย้อนหลัง 30 วัน + ทุกวันที่ 1 ของเดือน (ห้ามใช้ repo สาธารณะ เพราะมีข้อมูลลูกค้า)
ไฟล์สลิป/รูป: job เดียวกันดาวน์โหลดไฟล์ใหม่จาก Storage เก็บคู่กัน (ฐานข้อมูลสำรองเฉพาะตำแหน่งไฟล์ ไม่รวมตัวไฟล์)
ในแอป: ปุ่ม “ส่งออกข้อมูลทั้งหมด” (Excel/JSON) ให้เจ้าของเก็บเองเดือนละครั้ง
ทดสอบกู้คืน: เขียนขั้นตอน pg_restore ไว้ใน README และทดลองกู้คืนจริงอย่างน้อย 1 ครั้งก่อนส่งมอบ
งานสำรองรายวันยังช่วยให้มีการใช้งานฐานข้อมูลสม่ำเสมอ ลดความเสี่ยงโปรเจกต์ฟรีถูกพักเมื่อไม่มีการใช้งาน 7 วัน (เช่น ช่วงปิดร้านยาว)

## ส่วนที่ 13  การทดสอบและเกณฑ์ตรวจรับ
Unit (Vitest): สูตรในส่วนที่ 5 ทั้งหมด รวมกรณีบังคับข้อ 5.3 · ราคาพิเศษซ้อนช่วง · ปัดเศษมัดจำ · การแสดงวันที่ พ.ศ.
ฐานข้อมูล: ทดสอบ trigger กันจองเกิน รวมกรณีสองเครื่องบันทึกพร้อมกัน · ทดสอบ RLS ว่า anon เข้าไม่ได้
E2E (Playwright): สร้างการจอง → รับมัดจำ → เช็คอิน → รับเงินคงเหลือ → เช็คเอาท์ · จองเกินแล้วถูกปฏิเสธ · บันทึกตอนออฟไลน์แล้วซิงก์
อุปกรณ์จริง: iPhone (Safari, iOS 16.4+) · iPad · Android (Chrome) — ติดตั้งลงหน้าจอ รับแจ้งเตือน ใช้เน็ตมือถือที่โฮมสเตย์
### 13.1 Definition of Done
☐ ผ่านกรณีทดสอบข้อ 5.3 ครบ 3 กรณี
☐ ติดตั้งและใช้งานได้บน iPhone, iPad และ Android จริง
☐ แจ้งเตือนเข้าได้บน iPhone (ติดตั้งแล้ว) และ Android
☐ สองเครื่องเห็นข้อมูลตรงกันภายในไม่กี่วินาที
☐ ใช้งานออฟไลน์ได้และซิงก์กลับครบ
☐ backup รายวันทำงาน และทดลองกู้คืนสำเร็จ
☐ Lighthouse: Performance ≥ 90, Accessibility ≥ 95, Best Practices ≥ 95
☐ ไม่มีบริการใดเรียกเก็บเงิน และไม่มีการผูกบัตรเครดิต
☐ ส่งมอบคู่มือการใช้งาน (ภาษาไทย) และคู่มือดูแลระบบ

### 15.1 เนื้อหาไฟล์ CLAUDE.md (วางที่ root ของโปรเจกต์)
# คะนึงถึง ห้วยกุ๊บกั๊บ โฮมสเตย์ — กติกาโปรเจกต์
- อ่าน docs/SPEC.md ก่อนเริ่มงานทุกครั้ง; ดีไซน์อ้างอิง Requirement Form v1.1 ส่วนที่ 11–13
- ต้องฟรี 100%: ห้ามเพิ่มบริการ/แพ็กเกจที่มีค่าใช้จ่ายหรือบังคับผูกบัตร โดยไม่ถามก่อน
- เป้าหมายคือ PWA ที่ใช้ได้บน iOS 16.4+, iPadOS 16.4+, Android Chrome — ทดสอบ Safari ทุกครั้ง
- TypeScript strict; ห้ามใช้ any โดยไม่มีเหตุผล
- เงินเป็น integer สตางค์ (ไม่ใช้ float); วันที่เข้าพักเป็น date, timezone Asia/Bangkok
- กฎธุรกิจอยู่ใน src/domain เท่านั้น และต้องมี unit test; ห้ามคำนวณเงินซ้ำในคอมโพเนนต์
- ข้อความ UI ภาษาไทยทั้งหมดอยู่ใน src/i18n/th.ts
- เปลี่ยนฐานข้อมูลผ่านไฟล์ใน supabase/migrations เท่านั้น; เปิด RLS ทุกตารางใหม่
- ห้ามใส่ service role key หรือคีย์ลับในโค้ดฝั่งแอป
- ค่าที่ติดป้าย [ยืนยัน] ใน SPEC ให้ทำเป็นค่าตั้งค่า ไม่ฝังในโค้ด
- ก่อน commit: npm run lint && npm run test && npm run build ต้องผ่าน
- ทำงานทีละ Milestone (SPEC ส่วนที่ 14) และสรุปสิ่งที่ทำ/ค้างท้ายแต่ละงาน
